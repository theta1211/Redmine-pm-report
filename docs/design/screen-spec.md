# 画面仕様

対象は3画面：①レポート一覧画面（トップ）②レポート詳細画面 ③実行履歴画面。
すべてWindows統合認証を前提とし、ログイン画面は用意しない（未認証アクセスはIISが401を返す）。
操作権限は利用者間で区別せず、ログインしたPMは誰でも閲覧・エクスポート・手動再生成ができる
（要件定義のスコープどおり）。

## 1. レポート一覧画面（トップ）

### 目的
生成済みレポートの一覧確認、任意日の手動再生成、期間指定でのMarkdownエクスポート、
実行履歴画面への導線を提供する。

### レイアウト（イメージ）
```
┌──────────────────────────────────────────────────────────────┐
│ Redmine PM向け日次レポート                        [実行履歴]      │
├──────────────────────────────────────────────────────────────┤
│ 手動再生成  対象日:[____/__/__] [再生成]                          │
│ 期間エクスポート 開始:[____/__/__] 終了:[____/__/__] [エクスポート]  │
├──────────────────────────────────────────────────────────────┤
│ 対象日      │ステータス│新規│更新│作業時間│遅延│操作             │
│ 2026/09/14 │ 成功    │ 5  │ 8  │ 32.0h │ 3  │[詳細][MDエクスポート]│
│ 2026/09/11 │ 失敗    │ -  │ -  │  -    │ -  │[詳細]              │
└──────────────────────────────────────────────────────────────┘
```

### 表示項目
| 項目 | 内容 |
|---|---|
| 対象日 | レポート対象日（新しい日付から降順） |
| ステータス | 成功／失敗（失敗時は一覧上でも赤色表示） |
| 新規／更新／作業時間／遅延 | サマリの主要数値（失敗時は「-」） |
| 操作 | 詳細画面への遷移、単日Markdownエクスポート |

### 操作
- **手動再生成**：対象日（カレンダー入力）を指定し実行。保持期間（既定90日）より前の日付も入力自体は
  許可する。実行中は一覧上に「生成中」を表示し、完了後に一覧を更新する。同一対象日に対して自動バッチと
  手動再生成が重複した場合は、後着手した側が「他の処理が実行中のため再生成できません」という
  エラーを表示する（`sequence.md`7.）。
- **期間指定エクスポート**：開始日・終了日（最大31日以内）を指定し、Markdownファイルをダウンロードする。
  期間内に存在しない日（未生成・保持期間切れ）はスキップし、末尾に「対象外の日付」として一覧表示する。
- **実行履歴**：画面右上のリンクから実行履歴画面へ遷移する。

## 2. レポート詳細画面

### 目的
指定した対象日のレポート内容（新規登録・更新・作業時間集計・遅延チケット・サマリ）を確認する。

### レイアウト（イメージ）
```
┌──────────────────────────────────────────────────────────┐
│ ← 一覧に戻る   2026/09/14 のレポート        [Markdownエクスポート] │
├──────────────────────────────────────────────────────────┤
│ サマリ：新規5件／更新8件／作業時間合計32.0h／遅延3件(うち計算不可1件)│
├──────────────────────────────────────────────────────────┤
│【新規登録チケット】                                            │
│ #1234 ○○機能の追加  起票:佐藤 / タスク / 通常 / 担当:鈴木 / 期日:09/20│
├──────────────────────────────────────────────────────────┤
│【更新チケット】                                                │
│ #1230 △△バグ修正  ステータス: 新規 → 進行中                    │
├──────────────────────────────────────────────────────────┤
│【作業時間集計（担当者別）】                                       │
│ 鈴木: 7.5h　佐藤: 4.0h                                        │
├──────────────────────────────────────────────────────────┤
│【遅延チケット】（遅延時間の降順）                                  │
│ #1201 □□対応  担当:鈴木 期日:09/10（4日超過） 遅延時間:6.0h       │
│ #1198 ××改善  担当:未アサイン 期日:09/08（6日超過） 遅延時間:3.2h  │
│ ── 計算不可（工数未設定）──                                     │
│ #1190 △改修   担当:佐藤 期日:09/05（9日超過）                    │
└──────────────────────────────────────────────────────────┘
```

### 表示項目
| セクション | 項目 |
|---|---|
| サマリ | 新規件数・更新件数・作業時間合計・遅延件数（計算可能／計算不可の内訳） |
| 新規登録チケット | チケット番号・件名・起票者・トラッカー・優先度・担当者・期日 |
| 更新チケット | チケット番号・件名・変更点（ステータス／担当者の変更前後） |
| 作業時間集計 | 担当者別合計時間（時間、小数点1桁） |
| 遅延チケット | チケット番号・件名・担当者・期日・期日超過日数・遅延時間（計算可能なもの降順）／計算不可のものを末尾に別掲 |

### 操作
- **Markdownエクスポート**：表示中のレポート（単日）をMarkdownファイルとしてダウンロードする。
- 生成失敗（`status=failed`）のレポートを開いた場合は、上記セクションの代わりにエラーメッセージのみ表示する。

## 3. 実行履歴画面

### 目的
レポート生成バッチの実行履歴（自動・手動を問わず）を確認する。

### レイアウト（イメージ）
```
┌──────────────────────────────────────────────────────────┐
│ ← 一覧に戻る   実行履歴                                       │
├──────────────────────────────────────────────────────────┤
│ 実行日時         │対象日     │トリガー│実行者      │結果│エラー内容 │
│ 09/15 06:00:03  │09/14     │自動   │-          │成功│ -        │
│ 09/14 06:00:05  │09/13     │自動   │-          │失敗│Redmineへの接続に失敗しました│
│ 09/14 10:12:40  │09/13     │手動   │DOMAIN\sato│成功│ -        │
└──────────────────────────────────────────────────────────┘
```

### 表示項目
| 項目 | 内容 |
|---|---|
| 実行日時 | バッチ（自動／手動）の実行開始時刻 |
| 対象日 | 生成対象としたレポートの対象日 |
| トリガー | 自動（タスクスケジューラ）／手動（Web画面） |
| 実行者 | 手動時のみWindows認証のアカウント名（自動時は空欄） |
| 結果 | 成功／失敗 |
| エラー内容 | 失敗時のみ、要因が分かるメッセージ |

### 操作
- 一覧のみで、個別の操作（削除・再実行等）は設けない（保持期間経過後は自動的に一覧から消える）。
