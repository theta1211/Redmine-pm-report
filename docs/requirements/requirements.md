# 要件定義書：Redmine連携 PM向け日次レポート

## 1. 概要
Redmineの指定プロジェクト1件について、日々のチケット活動（新規登録・更新・ステータス変更）、
作業時間（Spent time）、遅延・期限超過チケットを集計し、PM向けの日次レポートを自動生成する仕組みを構築する。
Windowsのタスクスケジューラが定期的に起動するバッチ処理がRedmine REST APIから情報を取得してレポートを生成し、
PMはWeb画面でレポート一覧・詳細を閲覧したうえで、必要な回をMarkdownファイルとしてエクスポートできる。

本プロジェクトは、既存の
[Lychee-redmine-loop-engineering-](https://github.com/theta1211/Lychee-redmine-loop-engineering-)
（Redmineチケットを自動実装するループエンジン）の構成・設計方針
（npm workspacesによるモノレポ構成、DBを使わずJSONファイルで状態管理、Windowsタスクスケジューラでの定期実行、
Windows統合認証によるWeb画面アクセス制御）を踏襲する。

## 2. 登場する要素
| 要素 | 役割 |
|---|---|
| レポート生成バッチ | タスクスケジューラから起動され、対象日の活動をRedmine REST APIから収集し、レポートを生成・保存する |
| Web画面（レポート閲覧アプリ） | 生成済みレポートの一覧・詳細を表示し、Markdownファイルとしてエクスポートする。任意日の手動再生成もできる |
| Redmine（既存システム） | チケット・作業時間・活動履歴の取得元。新規構築はせず既存サーバーを利用する |
| 対象Redmineプロジェクト | レポート対象。当面は1プロジェクトに固定（設定ファイルで指定） |
| Windowsタスクスケジューラ | レポート生成バッチを一定間隔（日次）で起動するトリガー |
| PM（利用者） | Windows統合認証で識別。Web画面でレポートを閲覧・エクスポートする |

## 3. 全体構成図
```
[Windowsタスクスケジューラ] ──毎日決まった時刻に起動──▶ [レポート生成バッチ]
                                                              │
                                                              ▼
                                                     [Redmine API]
                                                     ・チケット一覧/更新履歴(journals)
                                                     ・作業時間(time_entries)
                                                     ・期限(due_date)超過チケット
                                                              │
                                                              ▼
                                                [レポートデータ(JSONファイル)] 対象日ごとに保存
                                                              ▲
                                                              │ 一覧取得・詳細取得・手動再生成の指示
[PM] ──Windows認証でログイン──▶ [Web画面(レポート閲覧アプリ)]
                                          │
                                          ▼
                                Markdownファイルとしてエクスポート（ダウンロード）
```

## 4. 機能要件

### 4.1 レポート生成バッチ
- Windowsタスクスケジューラにより1日1回、設定した時刻に起動される。
- 対象日は「起動日の前日（0:00〜23:59、Redmineサーバーのタイムゾーン基準）」を既定とする。
- 設定ファイルに指定された対象プロジェクト（1件固定）について、Redmine REST APIから以下を取得する。
  - 対象日に新規登録されたチケット（チケット番号・件名・起票者・優先度）
  - 対象日に更新されたチケット（ステータス変更・担当者変更等の変更内容、journalsベース）
  - 対象日に記録された作業時間（Spent time）を、担当者別・チケット別に集計
  - バッチ実行時点で期限（Due date）を超過している未完了チケット一覧（期限超過日数・担当者を含む）
- 取得した情報から、新規件数・更新件数・作業時間合計・遅延件数を含むサマリを作成する。
- 生成したレポートデータをJSONファイルとして`data/`配下に保存する（対象日・プロジェクト単位で1ファイル）。
- 同一対象日のレポートが既に存在する場合は再生成し上書きする（多重登録は行わない）。
- Redmineへの接続に失敗した場合や取得中にエラーが発生した場合は、レポートを「生成失敗」として記録し、
  次回のスケジュール起動には影響を与えない。
- レポート生成バッチが多重起動しないよう排他制御を行う。

### 4.2 Web画面（レポート閲覧アプリ）
- Windows統合認証でログインユーザーを識別する（認証基盤はWindows標準のものを利用）。
- 生成済みレポートを日付の一覧として表示する（新しい日付から順）。生成失敗もステータスとして表示する。
- 一覧から任意の日付を選び、レポート詳細（新規登録・更新・作業時間集計・遅延チケット・サマリ）を画面上で確認できる。
- 表示中のレポートをMarkdownファイルとしてエクスポート（ダウンロード）できる。
- 任意の対象日を指定してレポートを手動で再生成できる（自動生成が失敗した場合や欠測日のリカバリ用）。
- 手動再生成の実行状況（実行中・成功・失敗）を画面上で確認できる。

### 4.3 Redmine連携
- 既存のRedmineサーバーを利用する（URL・APIキーを設定情報として保持する）。
- チケット一覧・更新履歴（journals）・作業時間（time_entries）の取得に対応する。
- チケットのステータス変更・完了操作は本仕組みでは行わない（参照のみ）。

## 5. 非機能要件
- Web画面はLAN内に公開し、Windows統合認証でアクセス制御・利用者識別を行う。
- Redmine APIキー等の認証情報は平文コミットせず、設定ファイル／環境変数等で安全に管理する。
- レポート生成バッチの異常終了が後続の定期実行に影響しないこと。
- レポート生成バッチの多重起動防止（排他制御）を行うこと。
- 生成済みレポートの保持期間を設定可能とする（既定値は設計時に定める。期間経過後の扱いは詳細設計で規定）。
- DBは使用せず、JSONファイルで状態・レポートデータを管理する（Loop engineeringと同様の方針）。

## 6. 制約事項
- Redmine APIの利用制限（レートリミット等）に従う。
- 対象プロジェクトは1件固定とし、実行中の切り替えは設定ファイルの変更・再起動を要する。
- 1日1回の生成を基本とし、当日分もしくは過去の任意日の再生成は手動操作時のみ行う。
- レポートの内容は「チケットの新規登録・更新・ステータス変更」「作業時間集計」「遅延・期限超過チケット検出」に限る
  （チケットコメント本文の要約は対象外）。
- 完全無人で日次生成させるため、タスクスケジューラの実行ユーザーがRedmine APIへ到達可能なネットワーク環境にある
  ことを前提とする。

## 7. スコープ外
- 複数Redmineプロジェクトの同時対応（当面は1プロジェクト固定）。
- メール・Slack・Teams等、Web画面以外へのレポート配信・通知。
- チケットコメント（Notes）本文のAIによる要約。
- レポート内容に基づくチケットの自動操作（ステータス変更、リマインド送信等）。
- Redmine以外の課題管理ツールとの連携。
- 利用者ごとの個別権限設定（閲覧はPM向け共通とする）。
